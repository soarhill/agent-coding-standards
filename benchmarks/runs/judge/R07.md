## 1. Correctness — 30/30

- Bug 1: the original had two divergent mappers. The removed `editStatusText` is a shifted, truncated copy of the table mapper (its `0 → 'Pending'`, `1 → 'Vectorizing'`, `2 → 'Completed'`, `3 → 'Failed'` — four entries where the table has five, starting at the wrong code). The fix deletes the shifted duplicate and points the dialog at the surviving complete mapper:
  ```diff
  -      <p>Status: {{ editStatusText(editingFile.status) }}</p>
  +      <p>Status: {{ tableStatusText(editingFile.status) }}</p>
  ...
  -function editStatusText(status) {
  -  if (status === 0) return 'Pending'
  -  if (status === 1) return 'Vectorizing'
  -  if (status === 2) return 'Completed'
  -  if (status === 3) return 'Failed'
  -  return 'Unknown'
  -}
  ```
  Unifying onto the table mapper is the right direction: it is the one carrying the full code range (the dialog version had no mapping for the highest status at all). One source of truth means the two surfaces can no longer disagree.
- Bug 2: index-keyed `v-for` replaced with a stable identity key:
  ```diff
  -      v-for="(file, index) in files"
  -      :key="index"
  +      v-for="file in files"
  +      :key="file.id"
  ```
  With `:key="index"` on a reorderable list, Vue reuses DOM/`v-model` bindings positionally, which is exactly the reported "input stays attached to the wrong logical file". Keying by the row's own id re-binds inputs to logical files. The now-unused `index` binding is dropped.
- No styling, markup, API, or backend-code changes; Composition API retained; no dependencies.
