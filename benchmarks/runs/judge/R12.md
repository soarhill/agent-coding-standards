## 1. Correctness — 30/30

The rewrite inverts the big negative chain into positive form; every clause was checked for equivalence:

- Null guard preserved: `if (input == null || !isValid(input)) { throw new BusinessException(INVALID_CRITERIA); }` with `INVALID_CRITERIA` extracted as a constant of the same string value.
- Text rules: `hasText(criteria.category()) && !isTooLong(..., MAX_CATEGORY_LENGTH) && !isTooLong(keyword, MAX_KEYWORD_LENGTH) && !isTooLong(style, MAX_STYLE_LENGTH)` — `isTooLong(value, max)` retains the original `value != null && value.length() > max` body, so null keyword/style pass exactly as before; a null/blank category fails on `hasText` exactly as before.
- Price rules restructured but equivalent. Original invalid when `min != null && min < 0`, `max != null && max < 0`, or `min != null && max != null && min > max`. New:
  ```java
  private static boolean areValidPrices(Integer minPriceYuan, Integer maxPriceYuan) {
      return isNonNegative(minPriceYuan)
              && isNonNegative(maxPriceYuan)
              && (minPriceYuan == null
                  || maxPriceYuan == null
                  || minPriceYuan <= maxPriceYuan);
  }
  ```
  with `isNonNegative(p) = p == null || p >= 0` — the same three conditions in positive form (De Morgan; verified case by case over the null/non-null combinations).
- Priorities: `null → true`; otherwise `priorities.size() <= MAX_PRIORITIES && priorities.stream().noneMatch(priority -> isTooLong(priority, MAX_PRIORITY_LENGTH))` — exact inversion of `size() > 5 || anyMatch(tooLong)`.
- `normalizePriorities` is the identical stream; `normalizeLimit` is equivalent:
  ```java
  int requested = limit > 0 ? limit : DEFAULT_LIMIT;
  return Math.min(requested, MAX_RESULTS);
  ```
  (original `Math.max(1, Math.min(MAX_RESULTS, limit <= 0 ? 4 : limit))`: for `limit <= 0` both give 4; for `limit > 0` the old outer `Math.max(1, …)` is a no-op). The comment even states why the lower clamp disappears: `// The default (4) is within bounds, so no lower clamp is needed.`
- `trimToNull` compressed to `return hasText(value) ? value.trim() : null;` — same behavior.

No record, test, or signature changes.
