## 1. Correctness — 30/30

Behavior-equivalence was checked clause by clause against the removed code:

- Null guard preserved as short-circuit before the helpers:
  `if (input == null || isInvalid(input)) { throw new BusinessException("INVALID_CRITERIA"); }`
- Validation predicates unchanged and in the same order (no side effects, so order only affects nothing observable):
  - `!hasText(input.category()) || input.category().length() > MAX_CATEGORY_LENGTH || tooLong(input.keyword(), MAX_KEYWORD_LENGTH) || tooLong(input.style(), MAX_STYLE_LENGTH)` — identical to the original four text rules.
  - `hasInvalidPriceRange`: `(min != null && min < 0) || (max != null && max < 0) || (min != null && max != null && min > max)` — identical to original.
  - `hasInvalidPriorities`: `priorities != null && (priorities.size() > MAX_PRIORITIES || priorities.stream().anyMatch(value -> tooLong(value, MAX_PRIORITY_LENGTH)))` — identical (5 and 80 preserved via constants).
- `normalizedPriorities` is the identical stream (`filter(hasText) → map(String::trim) → toList()`, `List.of()` for null).
- Limit equivalence: original `Math.max(1, Math.min(MAX_RESULTS, input.limit() <= 0 ? 4 : input.limit()))`; new `normalizedLimit` returns `DEFAULT_LIMIT` for `limit <= 0`, else `Math.min(MAX_RESULTS, limit)`. For `limit > 0`, the old `Math.max(1, …)` was a no-op, so both forms agree on every input.

No test, record, or public-signature change.
