## 1. Correctness — 30/30

The two collapse-points in the original (failure and not-found both returned `null`, plus `System.err` swallow) are separated:

- Not-found → empty:
  `if (!response.found()) { return Optional.empty(); }`
- Transport failure → exception with cause:
  `catch (RuntimeException e) { throw new UpstreamUserServiceException("user lookup for id " + id + " failed", e); }`
- Unsuccessful/null response → exception:
  `if (response == null || !response.success()) { throw new UpstreamUserServiceException(... describeFailure(response)); }`
- Malformed success (`found` but no data — the literal NPE source, since old code returned `response.data()` which could be null and `user.nickname()` then NPE'd) → exception:
  `if (response.data() == null) { throw new UpstreamUserServiceException("... response reports the user as found but carries no data"); }`
- Profile path maps absence to the specified constant:
  `return userRpcService.findUser(userId).map(UserDto::nickname).orElse("Anonymous");`

The required signature is preserved: `public String getDisplayName(long userId)`. `Optional` is `java.util` — no new dependency. One behavioral nuance, documented and defensible: a user whose `nickname` is null now yields `"Anonymous"` (Javadoc: `"Anonymous" when the user genuinely does not exist (or has no nickname)"`), whereas the old code returned null at this layer and NPE'd at the call site — an improvement against the reported NPE class, not a regression against the stated contract.
